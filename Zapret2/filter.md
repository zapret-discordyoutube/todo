# 🧯 Фильтры профиля в Zapret 2: как движок решает, какой профиль обработает соединение

![[filter-check-chain.png]]

> [!info] О чём заметка
> Что такое фильтры [[Zapret2/profile|профиля]] в [[Zapret2/Zapret2|Zapret 2]], как по ним выбирается профиль для соединения, в каком порядке проверяются условия внутри профиля, что важнее чего и почему профиль иногда «не срабатывает». Здесь же — справочник всех фильтров. Подробно о списках: сайты — [[Zapret/hostlist|hostlist]], адреса — [[Zapret/ipset|ipset]]. Не путать с фильтрами захвата [[wf|WinDivert/nftables]] — те решают, какой трафик вообще попадёт в движок. Где выбор профиля стоит в общем конвейере, см. [[схема обработки трафика]].

## TL;DR

- **Профиль** = фильтры (к какому трафику он относится) + стратегия ([[desync|--lua-desync]]). Профили разделяются строкой `--new`.
- Соединение проверяется по профилям **сверху вниз**; его забирает **первый** профиль, у которого прошли все проверки. Не подошёл ни один — соединение достаётся скрытому профилю `no_action`, который ничего не делает.
- Внутри профиля условия объединяются логикой **И**, значения внутри одного фильтра — логикой **ИЛИ** (`--filter-tcp=80,443` — порт 80 или 443), несколько файлов списков одного вида — тоже **ИЛИ**.
- Порядок проверок внутри профиля: порты и протокол → исключения по адресам → адреса → (имя сайта известно?) → исключения по сайтам → сайты. **Исключение всегда сильнее включения.**
- Адрес известен с первого пакета, имя сайта — только с приветствия TLS. Пока имени нет, профиль со списком сайтов в выборе **не участвует**, и первые пакеты обрабатывает профиль ниже.

## Что такое фильтр профиля

[[Zapret2/profile|Профиль]] в Zapret 2 состоит из двух половин. **Фильтры** отвечают на вопрос «это соединение — моё?»: какие порты, какой протокол, какие адреса и сайты. **Действия** — строки [[desync|`--lua-desync`]] — отвечают на вопрос «что с ним делать». [[Zapret2/preset|Пресет]] — это несколько профилей подряд, каждый со своими фильтрами и своей стратегией. Полный список фильтров с синтаксисом — в [руководстве движка docs/manual.md](https://github.com/bol-van/zapret2/blob/master/docs/manual.md); ниже он пересказан с примерами.

> [!warning] Это не фильтры захвата WinDivert/nftables
> Отбор идёт на двух уровнях. Сначала [[wf|фильтр захвата]] (`--wf-*` на Windows, правила nftables/iptables на Linux) решает, какие пакеты вообще передать из системы в движок `nfqws2`/`winws2` — это грубое сито ради экономии. И только потом фильтры профиля из этой заметки выбирают, какой профиль и какая стратегия обработают уже захваченное соединение. Пакет, не прошедший фильтр захвата, до профилей не дойдёт.

## Как выбирается профиль

![[wiki-anim-z2-profilepick.svg|Анимация: четыре соединения ищут свой профиль сверху вниз; первый совпавший побеждает, если не подошёл ни один — скрытый no_action]]

Выбор делает функция `dp_match` в [исходнике nfq2/desync.c](https://github.com/bol-van/zapret2/blob/master/nfq2/desync.c). Порядок такой:

1. Соединение проверяется по профилям **сверху вниз**, от первого к последнему.
2. Первый профиль, у которого прошли все проверки, забирает соединение, и поиск прекращается. Профили ниже его уже не видят.
3. Если не подошёл ни один, соединение достаётся **скрытому профилю** `no_action` (служебный номер 0). Движок сам добавляет его последним при запуске; действий в нём нет, поэтому с соединением ничего не происходит. Подробнее — в [[exclusions|заметке об исключениях]].

Отсюда главное правило составления пресета: **узкие профили ставьте выше широких.** Профиль «YouTube» должен стоять над профилем «все сайты», иначе широкий профиль заберёт и YouTube.

> [!note] Выбор запоминается, но может пересматриваться
> Чтобы не искать профиль заново на каждый пакет, движок запоминает выбор в записи о соединении (conntrack — таблица, где движок хранит состояние каждого открытого соединения). Пересмотр возможен не больше двух раз за соединение: когда движок распознал протокол (например, понял, что это TLS) и когда узнал имя сайта. Именно поэтому профиль со списком сайтов может забрать соединение не с первого пакета, а позже.

## Порядок проверок внутри профиля

Диаграмма в начале заметки показывает шесть проверок, через которые проходит соединение в одном профиле. Условия, которых в профиле нет, считаются пройденными: профиль без списков подходит любому сайту и адресу на своих портах.

1. **Порты и протокол** — `--filter-tcp`, `--filter-udp`, `--filter-l7` и остальные фильтры по заголовкам пакета (справочник ниже).
2. **Исключения по адресам** — `--ipset-exclude`, `--ipset-exclude-ip`. Адрес нашёлся хотя бы в одном — профиль не подходит.
3. **Включения по адресам** — `--ipset`, `--ipset-ip`. Хватит совпадения в любом списке.
4. **Имя сайта уже известно?** Если у профиля есть списки сайтов, а имени у движка ещё нет, профиль сейчас не подходит. Он вернётся в выбор, когда имя появится.
5. **Исключения по сайтам** — `--hostlist-exclude`, `--hostlist-exclude-domains`.
6. **Включения по сайтам** — `--hostlist`, `--hostlist-domains`. Хватит совпадения в любом списке.

Не прошла хотя бы одна проверка — профиль не подходит, и соединение проверяет следующий профиль.

Проще говоря: внутри профиля всё должно совпасть, исключения проверяются раньше включений и побеждают их, а сайты проверяются только тогда, когда движок узнал имя.

## Адрес известен сразу, имя сайта — позже

Адрес сервера есть в самом первом пакете соединения. Имя сайта движок берёт из приветствия TLS (ClientHello — первое сообщение браузера в HTTPS-соединении, где открытым текстом написано имя сайта), из заголовка `Host` в HTTP или из приветствия QUIC. В обычном HTTPS-соединении это четвёртый пакет, после трёх пакетов установки соединения.

![[wiki-anim-profile-lists-timing.svg|Анимация: пока имени нет, первые пакеты соединения с youtube.com обрабатывает профиль «Все сайты (айпи)», а с приветствия TLS соединение переходит к профилю YouTube]]

Пример. В пресете два профиля: «YouTube» со списком сайтов и ниже «Все сайты (айпи)», у которого только исключения по адресам. Пока имени нет, «YouTube» в выборе не участвует, и первые пакеты соединения с youtube.com достаются «Все сайты (айпи)» — его стратегия успевает на них сработать. С приветствием TLS движок узнаёт имя, пересматривает выбор, и соединение переходит к «YouTube».

На практике это важно для стратегий, которые работают с самых первых пакетов (например, [[syndata]]). Если такая стратегия стоит в широком профиле по адресам, она сработает и для сайтов, у которых есть свой профиль по именам. Подробно этот случай разобран в [[exclusions|заметке об исключениях]].

## Что важнее чего: сводная таблица

| Правило | Что значит на практике |
|---|---|
| Профиль выше важнее профиля ниже | соединение забирает первый подошедший профиль |
| Исключение важнее включения | адрес или сайт из `--ipset-exclude`/`--hostlist-exclude` профиль не возьмёт, даже если он есть во включающем списке |
| Все условия профиля — через «И» | профиль с `--filter-tcp=443`, `--ipset` и `--hostlist` сработает, только если совпали порт, адрес и сайт |
| Несколько файлов одного вида — через «ИЛИ» | хватит совпадения в любом `--hostlist` (или любом `--ipset`) |
| Адреса решают раньше сайтов | профиль по адресам участвует в выборе с первого пакета, по сайтам — с приветствия TLS |
| В списке сайтов самая конкретная запись важнее общей | `!torrents.ru` сильнее `ru` — см. [[Zapret/hostlist\|hostlist]] |
| Пустой список = нет условия | профиль с пустым файлом списка подходит всем сайтам или адресам |
| Профиль с автосписком (`--hostlist-auto`) забирает соединения с известным именем всегда | его список решает только, применять ли стратегию |

## Фильтры по заголовкам пакета

Почти все фильтры принимают несколько значений через запятую, поддерживают инверсию (`~` перед значением — «всё, кроме») и `*` — «любое».

| Фильтр | Что отбирает | Синтаксис |
|:-------|:-------------|:----------|
| `--filter-l3` | версия IP-протокола | `ipv4` или `ipv6` (можно оба через запятую) |
| `--filter-tcp` | порты TCP | `[~]port[-port]` или `*`, через запятую |
| `--filter-udp` | порты UDP | `[~]port[-port]` или `*`, через запятую |
| `--filter-icmp` | тип и код ICMP | `type[:code]` или `*`, через запятую |
| `--filter-ipp` | номер «сырого» IP-протокола | `proto` или `*`, через запятую |
| `--filter-l7` | протокол соединения | `proto[,proto,…]` |
| `--filter-ssid` | имя Wi-Fi-сети (не на всех платформах) | `ssid[,ssid,…]` |

### `--filter-tcp` и `--filter-udp` — порты

Отбирают по портам TCP или UDP. Порт — номер «двери» на сервере: HTTPS обычно на 443, HTTP на 80, QUIC (HTTP/3) — UDP 443. Поддерживаются одиночный порт, диапазон `port1-port2`, инверсия `~port` и `*`.

```bash
--filter-tcp=80,443        # порт 80 или 443
--filter-tcp=1000-2000     # диапазон 1000–2000
--filter-tcp=~443          # все TCP-порты, кроме 443
--filter-tcp=*             # все TCP-порты
--filter-udp=443           # QUIC (UDP 443)
```

> [!important] Указание только TCP отключает UDP (и наоборот)
> Если в профиле есть `--filter-tcp`, но нет `--filter-udp`, UDP этот профиль не обрабатывает вовсе, и наоборот. Чтобы профиль работал с обоими, укажите оба фильтра (при необходимости с `*`).

### `--filter-l7` — протокол соединения

Отбирает по протоколу всего соединения — ярлыку, который движок ставит, распознав соединение по содержимому: `http`, `tls`, `quic`, `wireguard`, `mtproto`, `dns`, `stun`, `discord`, `dht`, `xmpp`, `dtls`, `bt`, `utp_bt`. Спецзначения: `all` — любой, `known` — любой распознанный, `unknown` — нераспознанный.

```bash
--filter-l7=tls            # только TLS/HTTPS
--filter-l7=tls,http       # TLS или HTTP
--filter-l7=quic           # только QUIC (HTTP/3)
```

Протокол распознаётся не с первого пакета, поэтому профиль с `--filter-l7` тоже может забрать соединение не сразу — это первый из двух пересмотров выбора. Разница между протоколом соединения и типом отдельного пакета разобрана в [[payload]].

### `--filter-l3`, `--filter-icmp`, `--filter-ipp`, `--filter-ssid`

```bash
--filter-l3=ipv6              # только IPv6
--filter-icmp=3:4,11          # ICMP type 3 code 4 или type 11 с любым кодом
--filter-ipp=47               # GRE (протокол 47)
--filter-ssid=MyHomeWiFi      # только в этой Wi-Fi-сети
```

`--filter-ipp` нужен для протоколов, которые не TCP, не UDP и не ICMP (подробнее — [[структура desync и диссекта]]). `--filter-ssid` доступен не на всех платформах.

## Списки IP и доменов

Кроме фильтров по заголовкам, профиль отбирают по спискам: адресов серверов — [[Zapret/ipset|ipset]] и сайтов — [[Zapret/hostlist|hostlist]]. У обоих есть исключающие варианты (`--ipset-exclude`, `--hostlist-exclude`): «профиль для всех, кроме…». На них строятся [[exclusions|исключения]] в пресетах.

| | ipset — адреса | hostlist — сайты |
|---|---|---|
| Что в строке | адрес или подсеть: `1.2.3.4`, `10.0.0.0/8`, IPv6 | домен: `youtube.com` (поддомены учитываются сами) |
| Когда решает | с первого пакета | с приветствия TLS / HTTP / QUIC |
| Префиксы | нет | `^домен` — без поддоменов, `!домен` — исключение из этого файла |
| Повтор записи | не мешает | работает первая запись домена |
| Список прямо в строке | `--ipset-ip`, `--ipset-exclude-ip` | `--hostlist-domains`, `--hostlist-exclude-domains` |
| Пустой файл | подходит всем адресам | подходит всем сайтам |

Один и тот же файл нельзя подключить в профиле дважды одного типа — с 31 октября 2026 года движок на это не запускается. Всё о формате, примерах и частых ошибках — в заметках [[Zapret/hostlist|hostlist]] и [[Zapret/ipset|ipset]].

## Внутрипрофильные фильтры: `--payload`, `--in-range`, `--out-range`

Кроме фильтров выбора профиля, есть фильтры **внутри** профиля. Они не решают, подходит ли профиль, а ограничивают отдельные строки [[desync|`--lua-desync`]]: к каким пакетам соединения применять действие. После определения такой фильтр действует на все следующие строки `--lua-desync` до переопределения.

- `--payload` — тип содержимого пакета (`tls_client_hello`, `http_req`, `all` и другие); полный разбор — [[payload]].
- `--out-range` и `--in-range` — какие по счёту пакеты обрабатывать; разбор — [[out-range]].
- Аргументы `dir` и `payload` у самой функции `--lua-desync` — то же на уровне одного действия.

```bash
--payload=tls_client_hello
--lua-desync=fake:blob=fake_default_tls:dir=out
```

## Примеры пресетов

### Сайты по списку и всё остальное по адресам

```bash
--filter-tcp=443 --hostlist=lists/youtube.txt
--lua-desync=multisplit
--new
--filter-tcp=80,443 --ipset-exclude=lists/ipset-ru.txt
--lua-desync=fake:blob=fake_default_tls
```

YouTube обрабатывает первый профиль, но только с приветствия TLS; до него и для всех остальных сайтов, кроме российских адресов, работает второй.

### Исключение внутри исключения

```bash
--filter-tcp=443
--hostlist-exclude-domains=ru,!torrents.ru
--lua-desync=fake:blob=fake_default_tls
```

Профиль для всех сайтов, кроме зоны `.ru` — но torrents.ru он всё-таки обрабатывает: `!` вычёркивает его из исключающего списка. Подробно — [[Zapret/hostlist|hostlist]].

### UDP Discord по адресам и портам

Профиль из стандартного пресета Zapret GUI «complex multidisorder»:

```bash
--name=Discord · UDP (обычно не нужно)
--filter-udp=443-65535
--ipset=lists/ipset-discord.txt
--out-range=-n4
--payload=all
--lua-desync=fake:blob=quic_google:repeats=12:ip_autottl=2,3-20:ip6_autottl=2,3-20:payload=all
```

В UDP-трафике голоса и видео нет приветствия TLS с именем сайта, поэтому профиль отбирает его по портам и адресам серверов Discord, а `--out-range=-n4` ограничивает стратегию первыми четырьмя пакетами.

## Как это выглядит в Zapret GUI

В программе условия профиля видны на его странице: строка с портами, списком и диапазонами пакетов в шапке и вкладка со списком сайтов или адресов. На вкладке «Текст профиля» видны сами строки фильтров так, как они записаны в пресете; кнопка **«Что это?»** рядом с «Сохранить текст профиля» объясняет, что значит каждая часть и что важнее чего, и открывает статьи вики. Порядок профилей меняется на странице «Профили пресета».
